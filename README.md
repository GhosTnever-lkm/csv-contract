# CSV Contract

Локальная проверка CSV по явным правилам проекта: обязательные колонки, типы ячеек, допустимые значения, диапазоны и уникальность ключей. Подходит для проверки выгрузки перед импортом, публикацией данных или запуском сборки.

Инструмент читает CSV последовательно и выдаёт текстовый или JSON-отчёт. В отчётах есть номер записи, название колонки и код проблемы; содержимое ячеек в отчёт и сообщения об ошибках не включается. Исходный CSV не изменяется. Python 3.10+; для работы не нужны внешние зависимости или сетевые запросы.

## Установка и быстрый старт

Из корня скачанного репозитория:

```bash
python -m pip install .
csv-contract examples/valid.csv --contract examples/contract.json
csv-contract examples/invalid.csv --contract examples/contract.json --json-out report.json --text-out report.txt
```

Вторая команда проверки показывает `INVALID` и возвращает код `1` — пример специально содержит ошибки. Установка через pip использует build-зависимости setuptools и wheel; при их отсутствии pip может загрузить их. Сам валидатор работает без сети.

Запуск исходников без установки:

```bash
# Linux / macOS
PYTHONPATH=src python -m csv_contract examples/valid.csv --contract examples/contract.json
```

```powershell
# Windows PowerShell
$env:PYTHONPATH = 'src'
python -m csv_contract examples/valid.csv --contract examples/contract.json
```

## Контракт

Это собственный небольшой формат версии 1, а не реализация JSON Schema:

```json
{
  "version": 1,
  "allow_extra_columns": false,
  "columns": {
    "id": {"type": "integer", "min": 1},
    "name": {"type": "string", "nonempty": true},
    "price": {"type": "decimal", "min": 0, "max": 10000},
    "active": {"type": "boolean"},
    "released": {"type": "date", "nullable": true},
    "category": {"type": "string", "enum": ["tool", "game"]},
    "note": {"type": "string", "required": false, "nullable": true}
  },
  "unique": [["id"], ["name", "category"]]
}
```

| Правило | Поведение |
| --- | --- |
| `type` | Обязательно: `string`, `integer`, `decimal`, `boolean` или `date`. |
| `required` | По умолчанию `true`: колонка должна быть в заголовке. `false` разрешает её отсутствие; присутствующая колонка всё равно проверяется. |
| `nullable` | По умолчанию `false`: пустая ячейка запрещена. `true` разрешает точно пустую строку; текст `null` остаётся обычным текстом. |
| `nonempty` | Только для `string`; запрещает непустую строку, состоящую из пробельных символов. Если `nullable:true`, точно пустая ячейка принимается. По умолчанию `false`. |
| `enum` | Непустой список значений объявленного типа. Для `date` используются строки ISO, для `decimal` — JSON-числа. Пустота контролируется `nullable`, а не `null` в enum. |
| `min`, `max` | Включительные конечные числовые границы только для `integer` и `decimal`. |
| `allow_extra_columns` | По умолчанию `false`: неизвестная колонка — находка `EXTRA_COLUMN`. |
| `unique` | Список одиночных или составных ключей. Повтор нормализованного ключа — `DUPLICATE_KEY`. Ключ с пустой nullable-ячейкой или ошибкой типа пропускается. |

Строки сохраняются без обрезки пробелов и сравниваются с учётом регистра. У чисел, дат и boolean внешние пробелы удаляются перед проверкой. `integer` принимает целое число с необязательным знаком; `decimal` — конечную десятичную запись, включая экспоненту. Числа сравниваются через `Decimal`, без преобразования денежных сумм в float. `boolean` принимает только `true`/`false` без учёта регистра. `date` требует календарную дату строго `YYYY-MM-DD`.

Неизвестные настройки, неверные типы правил, повторяющиеся JSON-ключи, несовместимые enum и некорректные границы отклоняются до чтения CSV.

## Формат, отчёты и коды выхода

CSV должен быть в UTF-8, допускается BOM. По умолчанию разделитель — запятая. Для других файлов:

```bash
csv-contract data.csv --contract contract.json --delimiter semicolon --format json
```

Доступны `comma`, `semicolon`, `tab`, `pipe`. Кавычки фиксированы: `"`; вложенная кавычка экранируется как `""`. Разрешены многострочные поля в кавычках. Незакрытая кавычка, кавычка внутри некавыченного поля и текст после закрывающей кавычки считаются ошибкой синтаксиса.

Пустые и повторяющиеся заголовки, отсутствующие/лишние колонки, короткие/длинные строки и ошибки значений попадают в отчёт. Если заголовок неоднозначен, проверки ячеек и ключей пропускаются; длина записей всё равно проверяется. Синтаксическая ошибка CSV прекращает обработку с кодом `2`, итоговый частичный отчёт не выдаётся.

Поле `row` — порядковый номер **CSV-записи**, начиная с `1` для заголовка. Это не номер физической строки: поле с переносом строки занимает одну запись.

| Код выхода | Значение |
| --- | --- |
| `0` | Данные соответствуют контракту. |
| `1` | CSV прочитан, найдены нарушения контракта. |
| `2` | Ошибка параметров, контракта, чтения, синтаксиса, лимитов или записи отчёта. |

`--format text` (по умолчанию) и `--format json` выбирают stdout. `--json-out` и `--text-out` дополнительно сохраняют отчёты и при коде `1`. Пути отчётов не могут совпадать с входным CSV, контрактом или друг с другом; проверяются и существующие hardlink/symlink-алиасы. Родительская папка должна существовать.

Сначала завершается проверка, затем отчёты записываются во временные файлы и заменяются по одному. Ошибка чтения или синтаксиса не перезаписывает прежний отчёт. Замена каждого отчёта атомарна, но **два отчёта не образуют общую транзакцию**: ошибка второй замены может возникнуть после успешной первой.

## Лимиты

| Ограничение | По умолчанию |
| --- | --- |
| CSV | 100 МиБ (`--max-bytes`) |
| Поле | 1 048 576 символов (`--max-field-chars`) |
| Физическая строка | 8 388 608 символов |
| Записи данных | 250 000 (`--max-rows`) |
| Подробности находок | 1 000 (`--max-findings`), до 2 МиБ |
| Контракт | 1 МиБ, до 256 колонок |
| Заголовок CSV | До 256 колонок; имя до 256 символов |
| Enum / уникальные ключи | До 10 000 значений в enum / до 32 определений ключей |

Все изменяемые лимиты должны быть положительными. При обрезке подробностей `truncated:true`; `finding_count` продолжает считать все обнаруженные нарушения. Проверка продолжается до конца файла либо до ошибки/лимита. Множества уникальных ключей хранятся в памяти и растут с числом записей; это потоковый ввод, но не константная память. Для больших выгрузок можно уменьшить `--max-rows`.

## Разработка

```bash
python -m unittest discover -s tests -v
```

Тесты не требуют установки пакета. CI запускает их на Windows и Ubuntu с Python 3.10 и 3.13, устанавливает пакет и проверяет CLI. Workflow релиза сверяет тег с версией, запускает тесты, собирает wheel/sdist и публикует `SHA256SUMS.txt`. Проверить скачанный файл можно `sha256sum -c SHA256SUMS.txt` или PowerShell `Get-FileHash -Algorithm SHA256`.

Поддержка формул, связей между таблицами, исправление данных, распознавание кодировки и полный JSON Schema не реализованы. Этот инструмент проверяет заданные правила, а не смысл или достоверность данных.
